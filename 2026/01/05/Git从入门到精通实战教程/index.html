Git从入门到精通实战教程

一、Git简介

1.1 什么是Git

Git是一款由Linus Torvalds于2005年开发的分布式版本控制系统，核心作用是追踪文件的修改历史、管理项目版本迭代，支持多人协同开发。与集中式版本控制系统（如SVN）不同，Git无需依赖中央服务器，每个用户的本地都拥有完整的项目仓库，可离线完成提交、分支等操作，极大提升了开发灵活性和效率。

1.2 Git的核心优势

  • 分布式架构：本地完整仓库，支持离线工作，数据安全性更高

  • 轻量高效：分支操作快速流畅，提交、回滚等指令执行速度快

  • 强大的分支管理：轻松实现功能开发、bug修复与主分支的隔离

  • 完整的版本追踪：可精确追溯每一次修改的作者、时间和内容

  • 跨平台兼容：支持Windows、MacOS、Linux等多种操作系统

二、Git安装与环境配置

2.1 下载与安装

2.1.1 Windows系统

  1. 访问Git官方下载页：https://git-scm.com/download/win

  2. 下载对应系统位数的安装包（32位/64位）

  3. 双击安装包，默认选项一路下一步即可（建议保留Git Bash组件，方便后续命令行操作）

  4. 安装完成后，打开Git Bash，输入git --version，若显示版本号则安装成功

2.1.2 MacOS系统

方法一：通过Homebrew安装（推荐）

  1. 若未安装Homebrew，先执行：/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

  2. 安装Git：brew install git

方法二：通过官方安装包

  1. 访问Git官方下载页：https://git-scm.com/download/mac

  2. 下载dmg安装包，双击安装即可

  3. 打开终端，输入git --version验证安装

2.1.3 Linux系统

Ubuntu/Debian系统：sudo apt-get update && sudo apt-get install git

CentOS/RHEL系统：sudo yum install git

安装完成后，输入git --version验证

2.2 首次环境配置

安装完成后，需要配置用户名和邮箱，用于标识提交记录的作者信息（建议与远程仓库平台如GitHub、Gitee的账号信息一致）

  1. 配置用户名：git config --global user.name "你的用户名"

  2. 配置邮箱：git config --global user.email "你的邮箱地址"

  3. 查看配置信息：git config --list，若能看到上述配置的用户名和邮箱，则配置成功

说明：—global参数表示全局配置，对当前用户的所有Git仓库生效；若需针对单个仓库配置，可进入仓库目录后去掉—global参数执行上述命令

三、Git核心概念

3.1 三大核心区域

  • 工作区（Working Directory）：本地项目的实际文件目录，日常开发的文件修改都在此区域进行，是我们能直接看到和操作的目录

  • 暂存区（Staging Area）：也叫索引区（Index），是临时存放待提交修改的缓冲区。通过git add命令可将工作区的修改添加到暂存区，暂存区的内容是下一次提交的候选内容

  • 版本库（Repository）：也叫本地仓库，是Git管理版本的核心区域，包含了所有提交的版本记录和分支信息。通过git commit命令可将暂存区的内容提交到版本库，生成新的版本记录

三者关系：工作区 →（git add）→ 暂存区 →（git commit）→ 版本库

3.2 版本记录相关概念

  • 提交（Commit）：将暂存区的内容固化为一个版本，每个提交都有一个唯一的SHA-1哈希值（40位字符串）作为版本标识，包含提交信息、作者、时间戳、父版本指针等信息

  • HEAD指针：指向当前分支的最新提交版本，可理解为“当前工作版本的指针”。通过移动HEAD指针，可切换到不同的历史版本

  • 分支（Branch）：独立的代码开发线，默认分支为main（或master）。创建分支后，可在分支上独立开发新功能或修复bug，完成后再合并到主分支，避免影响主分支的稳定性

四、Git基础操作

4.1 初始化本地仓库

若要将本地已有的项目目录转为Git仓库，执行以下步骤：

  1. 进入项目目录：cd /path/to/your/project（Windows系统可直接在项目目录右键打开Git Bash）

  2. 初始化仓库：git init

执行成功后，项目目录下会生成一个隐藏的.git目录（包含仓库的所有配置和版本信息），此时本地仓库已创建完成

4.2 文件状态查看与操作

Git中文件有四种状态：未跟踪（Untracked）、已跟踪（Tracked）、已修改（Modified）、已暂存（Staged）

4.2.1 查看文件状态

命令：git status

输出说明：

  • 红色字体：工作区未跟踪或已修改但未暂存的文件

  • 绿色字体：暂存区待提交的文件

  • “nothing to commit, working tree clean”：工作区和暂存区无未提交修改，工作区干净

简洁查看状态：git status -s（用简短的符号表示文件状态，更高效）

4.2.2 将文件添加到暂存区

  1. 添加单个文件：git add 文件名（如：git add README.md）

  2. 添加多个文件：git add 文件名1 文件名2（如：git add index.html style.css）

  3. 添加当前目录所有文件：git add .（最常用，注意末尾的点）

  4. 添加指定目录：git add 目录名/（如：git add src/，添加src目录下的所有文件）

4.2.3 将暂存区文件提交到版本库

命令：git commit -m "提交说明"

说明：

  • -m参数后紧跟提交说明，需清晰描述本次修改的内容（如：“feat: 新增用户登录页面”）

  • 提交说明建议遵循Conventional Commits规范，格式：<类型>: <描述>，常见类型：feat（新增功能）、fix（修复bug）、docs（文档修改）、style（代码格式调整）、refactor（代码重构）、test（新增测试）、chore（构建/工具配置修改）

  • 提交成功后，暂存区的内容会被固化为一个新的版本，版本库更新

快速提交（跳过暂存区，直接提交已跟踪文件的修改）：git commit -am "提交说明"（仅适用于已跟踪的文件，未跟踪文件需先执行git add）

4.3 查看提交历史

  1. 查看完整提交历史：git log（包含提交哈希值、作者、时间、提交说明等信息）

  2. 查看简洁提交历史（推荐）：git log --oneline（每条记录占一行，仅显示哈希值前7位和提交说明）

  3. 查看分支合并历史：git log --graph（以图形化方式展示分支关系和提交历史）

  4. 查看指定作者的提交历史：git log --author="用户名"

  5. 查看指定时间段的提交历史：git log --since="2026-01-01" --until="2026-01-05"

4.4 版本回滚

当需要撤销错误提交或回滚到历史版本时，可使用git reset命令，根据需求选择不同的参数：

4.4.1 步骤1：获取目标版本的哈希值

执行git log --oneline，找到需要回滚的版本对应的哈希值（前7位即可）

4.4.2 三种回滚模式

  1. 软回滚（—soft）：回滚版本库，保留暂存区和工作区的修改

命令：git reset --soft 目标版本哈希值

适用场景：误提交了不需要的修改，想撤销提交但保留已修改的内容，重新整理后提交

  1. 混合回滚（—mixed，默认模式）：回滚版本库和暂存区，保留工作区的修改

命令：git reset 目标版本哈希值（或git reset —mixed 目标版本哈希值）

适用场景：暂存区添加了错误的文件，想清空暂存区但保留工作区的修改

  1. 硬回滚（—hard）：回滚版本库、暂存区和工作区，丢弃所有未提交的修改

命令：git reset --hard 目标版本哈希值

适用场景：确定要彻底丢弃当前的所有修改，回到历史某个稳定版本

警告：—hard参数会永久丢弃未提交的修改，执行前请确认是否需要保留工作区内容

4.4.3 回滚后查看最新版本（已回滚后想恢复）

若执行硬回滚后后悔，想恢复到回滚前的版本，可通过git reflog命令查看所有操作记录（包括已删除的提交），找到目标版本的哈希值，再执行git reset —hard 哈希值即可恢复

五、Git分支管理

分支是Git的核心功能之一，合理使用分支可实现功能隔离开发、bug快速修复，提升团队协作效率。常见的分支策略有Git Flow、GitHub Flow等，核心思想是通过不同类型的分支承担不同的开发任务

5.1 分支基础操作

5.1.1 查看分支

  1. 查看本地分支：git branch（当前所在分支前会有*标记）

  2. 查看本地和远程分支：git branch -a（远程分支以remotes/开头）

  3. 查看分支关联关系：git branch -vv（查看本地分支对应的远程分支）

5.1.2 创建分支

命令：git branch 分支名（如：git branch feature/login，创建登录功能分支）

说明：创建分支后，仍停留在当前分支，需通过切换命令进入新分支

5.1.3 切换分支

方法一（传统）：git checkout 分支名（如：git checkout feature/login）

方法二（Git 2.23+推荐）：git switch 分支名（语义更清晰，专门用于切换分支）

注意：切换分支前，需确保当前分支的修改已提交或暂存，否则可能导致修改丢失或冲突

5.1.4 创建并切换分支（常用）

方法一：git checkout -b 分支名（如：git checkout -b feature/payment）

方法二：git switch -c 分支名（Git 2.23+支持）

说明：等价于先执行git branch 分支名，再执行git checkout/switch 分支名，一步完成创建和切换

5.1.5 删除分支

  1. 删除已合并到主分支的本地分支：git branch -d 分支名（如：git branch -d feature/login）

  2. 强制删除未合并的本地分支（丢弃分支内容）：git branch -D 分支名（如：git branch -D feature/test）

  3. 删除远程分支：git push origin -d 远程分支名（如：git push origin -d feature/login）

5.2 分支合并

当分支开发完成（如功能开发完毕、bug修复完成）后，需要将分支的修改合并到主分支（如main），常见的合并方式有git merge和git rebase两种

5.2.1 普通合并（git merge）

适用场景：合并功能分支到主分支，保留分支的提交历史

步骤：

  1. 切换到主分支：git switch main

  2. 拉取主分支最新代码（多人协作时必备）：git pull origin main

  3. 合并目标分支：git merge 目标分支名（如：git merge feature/login）

  4. 若合并成功，直接推送主分支到远程：git push origin main

5.2.2 解决合并冲突

当两个分支修改了同一文件的同一部分内容时，Git无法自动判断保留哪部分，会出现合并冲突，此时需要手动解决冲突：

  1. 合并冲突时，Git会提示“Automatic merge failed; fix conflicts and then commit the result.”

  2. 执行git status，找到标记为“both modified”的冲突文件

  3. 打开冲突文件，Git会用特殊符号标记冲突区域：

  1. 手动修改文件，删除冲突标记，保留需要的内容（可与团队成员协商）

  2. 解决完所有冲突后，将文件添加到暂存区：git add 冲突文件名

  3. 提交合并结果：git commit -m "merge: 合并登录功能分支，解决冲突"

  4. 推送主分支到远程：git push origin main

5.2.3 变基合并（git rebase）

适用场景：整理分支提交历史，使提交记录更线性、简洁（不推荐用于公共分支）

步骤（以将feature/login分支变基到main分支为例）：

  1. 切换到开发分支：git switch feature/login

  2. 拉取主分支最新代码：git pull origin main

  3. 执行变基：git rebase main

  4. 若出现冲突，解决冲突后执行：git add 冲突文件名，然后执行git rebase --continue继续变基（若想放弃变基，执行git rebase --abort）

  5. 变基完成后，推送分支到远程（由于变基修改了提交历史，需强制推送）：git push -f origin feature/login

  6. 切换到主分支，合并变基后的开发分支（此时合并会是快进合并，无冲突）：git switch main && git merge feature/login

警告：不要对已推送到远程的公共分支（如main、develop）执行变基操作，会覆盖公共提交历史，影响其他团队成员

六、远程仓库操作

远程仓库是存放项目代码的远程服务器，常见的远程仓库平台有GitHub、GitLab、Gitee等。通过Git可实现本地仓库与远程仓库的同步，支持多人协作开发

6.1 关联远程仓库

若本地已创建仓库，需关联远程仓库（远程仓库需提前在平台创建）：

命令：git remote add origin 远程仓库地址

说明：

  • origin是远程仓库的默认别名，可自定义（如：git remote add gitee 远程仓库地址）

  • 远程仓库地址可在平台仓库页面获取，支持HTTPS和SSH两种协议（SSH协议需配置密钥，无需每次输入账号密码）

查看已关联的远程仓库：git remote -v（显示远程仓库的拉取和推送地址）

修改远程仓库地址：git remote set-url origin 新的远程仓库地址

删除远程仓库关联：git remote rm origin

6.2 拉取远程代码（git pull）

拉取远程仓库的代码到本地，同步远程修改：

  1. 拉取指定远程分支到本地当前分支：git pull origin 远程分支名（如：git pull origin main）

  2. 拉取并关联远程分支（首次拉取时）：git pull --set-upstream origin 远程分支名（后续可直接执行git pull）

说明：git pull等价于git fetch（拉取远程代码到本地缓存）+ git merge（合并缓存到当前分支）

6.3 推送本地代码（git push）

将本地仓库的修改推送到远程仓库：

  1. 推送本地当前分支到指定远程分支：git push origin 本地分支名:远程分支名（若本地分支与远程分支同名，可简化为git push origin 分支名）

  2. 首次推送分支（关联上游分支）：git push -u origin 分支名（后续可直接执行git push）

  3. 强制推送（变基后或覆盖远程分支，谨慎使用）：git push -f origin 分支名（公共分支禁止使用）

6.4 克隆远程仓库（git clone）

将远程仓库完整克隆到本地（本地无仓库时使用）：

  1. 克隆远程仓库到当前目录：git clone 远程仓库地址

  2. 克隆到指定目录：git clone 远程仓库地址 目录名（如：git clone https://github.com/xxx/xxx.git git-tutorial）

说明：克隆完成后，本地会自动创建仓库，并关联远程仓库origin，无需再执行git init和git remote add

6.5 SSH密钥配置（免密登录）

使用HTTPS协议拉取/推送代码时，每次都需要输入账号密码，配置SSH密钥后可使用SSH协议免密操作：

6.5.1 生成SSH密钥

打开终端/Git Bash，执行：ssh-keygen -t rsa -C "你的邮箱地址"

执行后按三次回车（无需设置密码），会在用户目录下生成.ssh文件夹（Windows：C:\Users\用户名.ssh；Mac/Linux：~/.ssh），包含id_rsa（私钥，不可泄露）和id_rsa.pub（公钥）两个文件

6.5.2 配置公钥到远程平台

  1. 打开id_rsa.pub文件，复制其中的所有内容（公钥字符串）

  2. 登录远程仓库平台（如GitHub），进入个人设置 → SSH and GPG keys → New SSH key

  3. 粘贴公钥内容，设置标题（如“我的Windows电脑”），点击添加即可

6.5.3 验证配置

执行：ssh -T git@github.com（GitHub）或ssh -T git@gitee.com（Gitee）

若显示“Hi 用户名! You’ve successfully authenticated…”，则配置成功，后续可使用SSH地址拉取/推送代码

七、Git高级技巧

7.1 忽略文件（.gitignore）

项目中有些文件不需要Git跟踪（如日志文件、编译产物、IDE配置文件等），可通过创建.gitignore文件指定忽略规则

7.1.1 创建.gitignore文件

在项目根目录创建名为.gitignore的文件（无文件名，后缀为ignore）

7.1.2 常见忽略规则

说明：

  • 以#开头的是注释

  • *.xxx：忽略所有后缀为xxx的文件

  • 目录名/：忽略整个目录

  • !文件名：不忽略指定文件（覆盖前面的忽略规则）

注意：.gitignore文件仅对未跟踪的文件生效，若文件已被跟踪，需先执行git rm --cached 文件名移除跟踪，再添加到.gitignore

7.2 暂存工作区修改（git stash）

当需要切换分支但当前工作区的修改未完成，不想提交时，可使用git stash将修改暂存起来，切换分支完成后再恢复

7.2.1 暂存修改

  1. 暂存当前工作区所有修改：git stash save "暂存说明"（说明可选，建议添加，便于区分暂存记录）

  2. 暂存指定文件：git stash save -p "暂存说明"（交互式选择需要暂存的修改）

7.2.2 查看暂存列表

命令：git stash list（显示所有暂存记录，格式：stash@{0}: On 分支名: 暂存说明）

7.2.3 恢复暂存的修改

  1. 恢复最近一次暂存（保留暂存记录）：git stash apply

  2. 恢复指定暂存（保留暂存记录）：git stash apply stash@{n}（n为暂存序号，如stash@{1}）

  3. 恢复最近一次暂存（删除暂存记录）：git stash pop（推荐，恢复后自动清理暂存）

  4. 恢复指定暂存（删除暂存记录）：git stash pop stash@{n}

7.2.4 删除暂存记录

  1. 删除最近一次暂存：git stash drop

  2. 删除指定暂存：git stash drop stash@{n}

  3. 清空所有暂存：git stash clear

7.3 查看文件修改内容（git diff）

查看工作区、暂存区、版本库之间的文件修改差异：

  1. 查看工作区与暂存区的差异：git diff（未指定文件时查看所有文件，指定文件：git diff 文件名）

  2. 查看暂存区与版本库的差异：git diff --cached（或git diff —staged）

  3. 查看工作区与版本库的差异：git diff HEAD

  4. 查看两个版本之间的差异：git diff 版本1哈希值 版本2哈希值（如：git diff a1b2c3d e4f5g6h）

  5. 查看两个分支之间的差异：git diff 分支1 分支2（如：git diff main feature/login）

7.4 撤销文件修改

根据文件所处状态，使用不同的命令撤销修改：

  1. 撤销工作区未暂存的修改（已跟踪文件）：git checkout -- 文件名（或git restore 文件名，Git 2.23+支持）

  2. 撤销暂存区的修改（将文件从暂存区放回工作区）：git reset HEAD 文件名（或git restore —staged 文件名，Git 2.23+支持）

  3. 撤销已提交的修改（但保留修改内容）：git reset --soft HEAD~1（HEAD~1表示上一个版本，HEAD~2表示上上个版本，以此类推）

八、团队协作规范

良好的协作规范可提升团队开发效率，减少冲突和沟通成本，以下是通用的Git协作规范建议

8.1 分支命名规范

采用“分支类型/功能描述”的格式，分支类型包括：

  • main：主分支，存放稳定的生产环境代码，禁止直接在主分支开发

  • develop：开发分支，团队协作的主分支，由功能分支合并而来

  • feature/xxx：功能分支，用于开发新功能（如：feature/user-register、feature/payment）

  • bugfix/xxx：bug修复分支，用于修复开发分支的bug（如：bugfix/login-error、bugfix/data-query）

  • release/xxx：发布分支，用于版本发布前的准备（如：release/v1.0.0、release/v2.1.0）

  • hotfix/xxx：紧急修复分支，用于修复生产环境的紧急bug（如：hotfix/payment-crash、hotfix/login-timeout）

8.2 提交信息规范

遵循Conventional Commits规范，格式：<类型>[可选作用域]: <描述>

  1. 类型（必填）：

  • feat：新增功能

  • fix：修复bug

  • docs：文档修改（如README、注释）

  • style：代码格式调整（不影响代码逻辑，如缩进、空格、命名）

  • refactor：代码重构（既不是新增功能，也不是修复bug）

  • test：新增或修改测试用例

  • chore：构建流程、依赖管理、工具配置等修改（不影响代码逻辑）

  • perf：性能优化

  • revert：撤销之前的提交

  1. 作用域（可选）：指定修改的模块（如：user、payment、login）

  2. 描述（必填）：简洁明了地描述本次修改的内容（用现在时，不超过50个字符）

示例：

  • feat(user): 新增用户注册功能

  • fix(payment): 修复支付失败的bug

  • docs: 更新README中的安装步骤

  • refactor(login): 重构登录验证逻辑

  • chore: 升级axios依赖到1.6.0

8.3 协作流程建议（GitHub Flow简化版）

  1. 从main/develop分支拉取最新代码

  2. 创建功能分支（feature/xxx）或bugfix分支（bugfix/xxx）

  3. 在分支上开发，定期提交代码（提交信息遵循规范）

  4. 开发完成后，推送分支到远程仓库

  5. 在远程平台（GitHub/GitLab）创建Pull Request（PR）/Merge Request（MR）

  6. 团队成员进行代码评审（Code Review）

  7. 根据评审意见修改代码，重新推送

  8. 评审通过后，合并分支到main/develop分支

  9. 删除远程和本地的功能/bugfix分支

九、常见问题与解决方案

Q1：提交时提示“Author identity unknown”

原因：未配置用户名和邮箱

解决方案：执行以下命令配置全局用户名和邮箱

git config --global user.name "你的用户名"

git config --global user.email "你的邮箱地址"

Q2：如何撤销已推送到远程的提交

解决方案：

  1. 回滚到目标版本：git reset --hard 目标版本哈希值

  2. 强制推送到远程：git push -f origin 分支名

警告：此操作会覆盖远程分支的提交历史，若其他团队成员已拉取该分支，会导致冲突，需提前沟通

更安全的方式：使用git revert创建一个新的提交来撤销之前的提交（不修改历史）

git revert 要撤销的提交哈希值

git push origin 分支名

Q3：拉取远程新分支到本地

解决方案：

  1. 拉取远程所有分支信息：git fetch origin

  2. 创建并切换到远程新分支对应的本地分支：git checkout -b 本地分支名 origin/远程分支名

或（Git 2.23+）：git switch -c 本地分支名 origin/远程分支名

Q4：git pull时提示“fatal: refusing to merge unrelated histories”

原因：本地仓库和远程仓库的提交历史无关联（如本地已初始化仓库，远程仓库也有提交）

解决方案：拉取时添加—allow-unrelated-histories参数

git pull origin 分支名 --allow-unrelated-histories

拉取后若有冲突，解决冲突后提交即可

Q5：如何删除已跟踪的文件并添加到.gitignore

解决方案：

  1. 移除文件的跟踪（保留本地文件）：git rm --cached 文件名

  2. 将文件添加到.gitignore

  3. 提交修改：git commit -m "chore: 移除xxx文件的跟踪并添加到.gitignore"

  4. 推送远程：git push origin 分支名

  • git status：查看文件状态

  • git add 文件名/.：添加文件到暂存区

  • git commit -m “说明”：提交暂存区到版本库

  • git commit -am “说明”：快速提交已跟踪文件

  • git checkout/switch 分支名：切换分支

  • git checkout/switch -c 分支名：创建并切换分支

  • git merge 分支名：合并分支

  • git rebase 分支名：变基合并分支

  • git branch -d/-D 分支名：删除本地分支

远程同步

  • git pull origin 分支名：拉取远程代码

  • git push origin 分支名：推送本地代码

  • git push -u origin 分支名：首次推送关联分支

  • git push -f origin 分支名：强制推送（谨慎使用）

高级操作

  • git stash save “说明”：暂存工作区修改

  • git stash list：查看暂存列表

  • git stash apply/pop：恢复暂存修改

  • git diff：查看文件修改差异

  • git rm —cached 文件名：移除文件跟踪
